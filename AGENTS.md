# Project notes

Turborepo starter kit: pnpm workspaces + Next.js (App Router) + Tailwind CSS v4 + shadcn/ui.

## Layout

- `apps/web` — Next.js app. Imports UI from `@repo/ui`.
- `packages/ui` — shared components. shadcn components live in `src/components/ui`.
  Theme + Tailwind `@source` scanning live in `src/styles/globals.css`.
- `packages/db` — Drizzle ORM schema, migrations and repositories (Postgres).
- `packages/eslint-config`, `packages/typescript-config` — shared configs.

## Commands

- `pnpm install` / `pnpm dev` / `pnpm build` / `pnpm lint` / `pnpm check-types` / `pnpm format`
- Filter a single workspace: `pnpm --filter web dev`, `pnpm --filter @repo/ui check-types`

## Conventions

- Add shadcn components from `packages/ui`: `cd packages/ui && pnpm dlx shadcn@latest add <name>`.
  Then normalize any `from "cn"` import to `from "@repo/ui/lib/utils"` and drop the `cn` dep.
- Import in apps via aliases: `@repo/ui/components/ui/button`, `@repo/ui/lib/utils`.
- TS config is TypeScript 7: do NOT use `baseUrl` (removed). Use relative `paths` entries.
- `apps/web/AGENTS.md` and `CLAUDE.md` are auto-generated by `next dev`; keep them committed.

## Tooling (Phase 1 & 2)

- Version catalog: declare shared versions in `pnpm-workspace.yaml` `catalog:`, reference with `"catalog:"`.
- Git hooks: Husky (`.husky/pre-commit` -> lint-staged, `.husky/commit-msg` -> commitlint).
  `prepare: husky` script runs on install. Commit messages must be Conventional Commits.
- Unit tests: Vitest in `packages/ui` (`*.test.ts(x)`, config `vitest.config.ts`, jsdom + Testing Library).
  `pnpm test` / `pnpm test:coverage`. Tests are type-checked via `types: ["vitest/globals", "@testing-library/jest-dom"]`.
- E2E: Playwright in `apps/web/e2e` (`playwright.config.ts` uses `pnpm start`, so build first).
  Install browser once: `pnpm --filter web exec playwright install chromium`.
- `packages/ui` uses `moduleResolution: "Bundler"` (consumed as source by Next, not built).
- Turbo tasks: build, lint, check-types, test, test:coverage, test:e2e, dev, clean.

## Phase 3 — Env & validators

- `packages/validators` — shared Zod v4 schemas (`src/schemas/*`), barrel `src/index.ts`.
  Exposed as `@repo/validators` and `@repo/validators/schemas/*`. Node-env Vitest.
- `packages/env` — t3-env (`@t3-oss/env-core`) factories `createServerEnv(runtimeEnv?)` /
  `createClientEnv(runtimeEnv)`. Schemas live in `src/core.ts`. Passing the env object
  explicitly keeps it testable (no reliance on `process.env`).
- `apps/web/env.ts` — `env` (server) and `clientEnv` (NEXT_PUBLIC_*). Client values must be
  referenced statically so Next inlines them.
- Example flow: `apps/web/lib/contact.ts` (validation + logic) is used by both the route
  handler `app/api/contact/route.ts` and the server action `lib/actions.ts`.
- Zod v4 note: `z.email()` validates immediately, so normalize first via
  `z.string().trim().toLowerCase().pipe(z.email())`.
- `apps/web` now has Vitest (node env) for `lib/**` and `app/**` tests.
- Packages with a `check-types` using `process.env` need `@types/node` devDependency.

## Phase 6 — CI (GitHub Actions)

- Workflow: `.github/workflows/ci.yml`, two jobs: `ci` (format:check, lint, check-types,
  test, build) and `e2e` (Playwright chromium + upload report artifact).
- `pnpm/action-setup@v6` reads `packageManager` from package.json (do NOT also pass `version`).
- Node via `actions/setup-node@v7` `node-version-file: .nvmrc`; pnpm store cached via `cache: pnpm`.
- `.turbo` cached with `actions/cache@v6` (sha key + restore-keys) to reuse task results.
- Telemetry disabled via `TURBO_TELEMETRY_DISABLED` / `NEXT_TELEMETRY_DISABLED`.
- Validate workflow edits with actionlint (binary, no docker needed):
  `curl -sSL https://github.com/rhysd/actionlint/releases/latest/download/actionlint_<ver>_linux_amd64.tar.gz`.
- `pnpm format:check` is part of CI; run `pnpm format` before committing docs/code.

## Phase 6 fix — pnpm 11 supply-chain policy

- CI installs with the pinned pnpm from `packageManager` (pnpm 11.25.0), which enforces
  `minimumReleaseAge` (default 24h). A lockfile generated by pnpm 9 may contain packages
  published within that window and fail with `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`.
- Always regenerate the lockfile with the pinned pnpm: `corepack pnpm clean --lockfile && corepack pnpm install`.
- Local `pnpm` on this machine is 9.15.4; use `corepack pnpm ...` to match CI. (CI uses pnpm/action-setup.)
- Lockfile is `lockfileVersion: '9.0'`; pnpm 11 still writes v9 format.

## Phase 4 — Data layer (Drizzle + Postgres)

- `packages/db` — `@repo/db`. Schema `src/schema/*`, repositories `src/repositories/*`,
  client factory `src/client.ts`, migrations in `drizzle/` (drizzle-kit generate output).
- Subpath exports: `@repo/db` (client + repositories + schema), `@repo/db/client`,
  `@repo/db/schema`, `@repo/db/repositories/*`, `@repo/db/migrate`, `@repo/db/testing`.
- `src/migrate.ts` reads files from disk, so it is intentionally NOT in the barrel `index.ts`
  (bundling it into a Next route fails: `Module not found: Can't resolve '../drizzle'`).
- Tests use PGlite (`@electric-sql/pglite`) via `createTestDb()` in `src/testing.ts`: it runs
  the real migrations against an in-process Postgres, so no server is needed. Keep
  `drizzle-orm/pglite` imports out of the production entry.
- Production driver is postgres.js (`src/client.ts`, `createDbClient(url)`); `postgres` is
  listed in `next.config.js` `serverExternalPackages`.
- `DATABASE_URL` is optional. `apps/web/lib/db.ts` `getDb()`/`getContactRepository()` return
  `null` without it, so `submitContact` validates and skips writes — dev/CI need no database.
- `submitContact(input, { repository })` persists when a repository is passed; the route
  handler and server action both inject `getContactRepository()`.
- `drizzle.config.ts` sets `out: ./drizzle`, `dialect: postgresql`, `schema: ./src/schema/*.ts`.
- pnpm 11 blocks install scripts; `pnpm-workspace.yaml` `allowBuilds: { esbuild: true }` is
  required so esbuild's postinstall can fetch its binary.
- Migrations must be committed. To apply: `pnpm --filter @repo/db db:migrate`.
- Verified end-to-end against a real Postgres 17: `drizzle-kit migrate` applies the SQL, and
  a `POST /api/contact` with `DATABASE_URL` set returns the row `id` and writes the row.

## Phase 5 — App structure & UX

- Route groups in `apps/web/app`: `(marketing)` (site header + footer) and `(app)` (sidebar +
  top bar). Groups do not change URLs; the landing page lives in `(marketing)/page.tsx`.
- App shell: `components/site-header.tsx`, `site-footer.tsx`, `app-nav.tsx`,
  `app-mobile-nav.tsx`; site metadata in `lib/site.ts`, date formatting in `lib/format.ts`.
- Feedback via Sonner. `packages/ui/src/components/ui/sonner.tsx` re-exports it; `<Toaster />`
  is mounted once in `apps/web/app/layout.tsx`. Client code calls `toast()` from `sonner`,
  so apps that use toasts need `sonner` in their own `dependencies`.
- Special files: `error.tsx`, `global-error.tsx`, `not-found.tsx`, `(marketing)/loading.tsx`,
  `(app)/dashboard/loading.tsx`, plus SEO routes `sitemap.ts`, `robots.ts`, `manifest.ts`,
  `opengraph-image.tsx` (all convention-based, no static files).
- `dashboard` and `messages` set `export const dynamic = "force-dynamic"` so they read the
  database at request time instead of a build-time snapshot.
- **React dedupe is mandatory.** `pnpm-workspace.yaml` `overrides: { react: 19.2.8,
react-dom: 19.2.8 }` pins one React across the tree. Without it, `@floating-ui/react-dom`
  (via `radix-ui`) pulls a newer React minor and the `@repo/ui` `Toaster` silently stops
  rendering — it mounts its own React copy, so `toast()` calls never appear. Keep the override
  in sync with the catalog versions.
- After changing overrides, do a clean install (`rm -rf node_modules apps/*/node_modules
packages/*/node_modules && pnpm install`) and a clean rebuild (`rm -rf apps/web/.next`),
  or the old server keeps serving a stale `.next` and 500s on dynamic routes.
- E2E in `apps/web/e2e`: `home.spec.ts` (hero, cards, theme toggle, contact toast) and
  `app-structure.spec.ts` (route groups, 404, sitemap/robots/OG). Playwright `reuseExistingServer`
  reuses any server on :3000 — kill stray `next start` processes before running e2e locally.
- Pushing to `origin` (GitHub): `GITHUB_TOKEN` is read-only here and is rejected with 403;
  use `GITHUB_PAT` instead, e.g.
  `git push https://x-access-token:$GITHUB_PAT@github.com/openlynkid/Turborepo-starterkit.git main`.

## Phase 4b — Component library expansion (shadcn)

- New components added to `packages/ui/src/components/ui`: `form`, `table`, `tabs`,
  `select`, `checkbox`, `switch`, `textarea`, `alert`, `accordion`, `progress`
  (`card` was regenerated by the CLI).
- The shadcn CLI (`pnpm dlx shadcn@latest add <name>` run from `packages/ui`) writes a
  bare `import { cn } from "cn"` and adds a `cn` dependency. Always rewrite it to
  `import { cn } from "@repo/ui/lib/utils"` and drop the `cn` package afterwards —
  otherwise `pnpm check-types` fails to resolve `cn`.
- `form` needs `react-hook-form` + `@hookform/resolvers`; both are now in the catalog and
  declared in `packages/ui/package.json` and `apps/web/package.json`. The CLI add for
  `form` timed out, so `packages/ui/src/components/ui/form.tsx` is hand-written but
  matches the upstream shadcn source.
- `apps/web/components/contact-form.tsx` was rewritten on top of `Form` + react-hook-form
  with `zodResolver(contactFormSchema)`. Server-side errors from the action are pushed
  into the form with `form.setError`. The e2e selectors (`getByLabel("Name")` etc.) still
  match because `FormLabel` sets `htmlFor` to the control id.
- New page `apps/web/app/(app)/components/page.tsx` renders `components/ui-showcase.tsx`
  (tabs/table/switch/checkbox/select/progress/accordion/alert/buttons) so the new
  components are exercised by e2e. Added to `appNav` in `lib/site.ts` and to the icon map

## Security audit (2026-11)

Findings and the resulting changes. Re-run `pnpm audit` after any dependency bump.

- **Next.js advisories (critical/high).** `next` 16.3.8 was affected by
  GHSA-2464-fhr4-w9xw and GHSA-673q-mjm6-r5xr (unauthenticated RCE, patched in
  16.4.1) and GHSA-p3m5-59mp-jv5r (server-action DoS, patched in 16.4.1).
  The catalog now pins `next: 16.4.5` (covers `eslint-config-next` too).
- **Transitive advisories with no upstream fix.** `esbuild@0.18.20` came in via
  `drizzle-kit > @esbuild-kit/core-utils` (GHSA-67mh-4wv8-2f99) and
  `minimatch@10.x` via `eslint > @eslint/config-array`
  (GHSA-g3hv-75wg-m249). Neither upstream has released a fix, so
  `pnpm-workspace.yaml` pins them through `overrides` (`esbuild: ^0.25.0`,
  `minimatch: ^11.0.1`). `pnpm audit` is now clean.
- **Security headers.** `apps/web/next.config.js` sets a baseline
  `Content-Security-Policy` plus `X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, `Strict-Transport-Security`, `Permissions-Policy` and
  disables `X-Powered-By`. Covered by the `security` e2e block in
  `apps/web/e2e/app-structure.spec.ts`. The CSP keeps `'unsafe-inline'` for
  scripts (static pages can't use nonces); see Phase 8 for the nonce upgrade
  path.
- **CI permissions.** `.github/workflows/ci.yml` now declares
  `permissions: contents: read`. `release.yml` keeps `contents/pull-requests:
write` because changesets opens a PR.
- Clean by inspection: no committed secrets, `.env*` ignored (only
  `.env.example` tracked), Drizzle queries are parameterized, no
  `dangerouslySetInnerHTML`/`eval`, env validated with t3-env + Zod and
  server/client values kept separate.

## Phase 8 — Production hardening

Closed the gaps flagged as "accepted for a starter kit" in the Phase 7 audit.
All features stay **opt-in**, so local dev and CI need no new setup.

- **Auth (opt-in).** `SESSION_SECRET` + `ADMIN_EMAIL` + `ADMIN_PASSWORD` turn on
  a single-admin login for the app section. `apps/web/lib/session.ts` signs an
  HMAC-SHA256 session in an `HttpOnly`, `SameSite=Lax` cookie; credentials are
  compared in constant time. Two layers: `apps/web/proxy.ts` (Next.js 16's
  Proxy — `middleware.ts` is deprecated/renamed, and `runtime` is not a valid
  Proxy config option) does an optimistic redirect, and the `(app)` layout does
  the authoritative server-side check. `/login` shows a "Continue without auth"
  shortcut when auth is off. Verified live: login → `/dashboard`, sign out →
  `/login`, wrong password → error.
- **Rate limiting.** `apps/web/lib/rate-limit.ts` is a fixed-window limiter
  (in-process Map; `RATE_LIMIT_MAX` / `RATE_LIMIT_WINDOW_MS`). `lib/contact-guard.ts`
  applies it per client IP (`x-forwarded-for`) for both the route handler and the
  server action. Behind multiple instances add a shared limit at the edge too.
- **CAPTCHA (opt-in).** `lib/turnstile.ts` verifies Cloudflare Turnstile tokens
  (fails closed) when `TURNSTILE_SECRET_KEY` is set; `components/turnstile.tsx`
  renders the widget when `NEXT_PUBLIC_TURNSTILE_SITE_KEY` is set.
- **Health + errors.** `GET /api/health` reports app + DB status via
  `@repo/db` `pingDatabase` (added in `packages/db/src/client.ts`).
  `apps/web/instrumentation.ts` `onRequestError` logs structured server errors.
- **Deploy migrations.** `packages/db/scripts/migrate.mjs` (`db:migrate:deploy`)
  runs `drizzle-kit migrate` and **skips cleanly when `DATABASE_URL` is unset**
  (the drizzle config otherwise falls back to localhost and would fail the
  build). It also skips when `VERCEL_ENV` is set but is not `production`, so
  preview deploys never migrate. `apps/web/vercel.json` calls it after the build.
- **Env split.** Client values moved to `apps/web/client-env.ts` so client
  components don't bundle the server schema; `apps/web/env.ts` is server-only.
- **Turbo.** `turbo.json` `globalEnv` now lists `NODE_ENV`, `DATABASE_URL` and
  `VERCEL_ENV`. `packages/db/eslint.config.mjs` adds Node globals for
  `scripts/**/*.mjs`.
- **Tests.** New unit tests for session, rate-limit, turnstile, contact-guard,
  proxy, health route and `pingDatabase`; e2e adds CSP, health and auth blocks.
  `playwright.config.ts` raises `RATE_LIMIT_MAX` for the shared e2e server so
  functional tests don't trip the limiter (the limiter has its own unit tests).
  Full suite: 41 unit tests + 23 e2e, all green.

## Audit follow-ups (2026-11, second pass)

- **Login rate limiting.** The contact endpoint was limited but login was not.
  `lib/rate-limit.ts` now exports `loginRateLimiter`
  (`LOGIN_RATE_LIMIT_MAX` / `LOGIN_RATE_LIMIT_WINDOW_MS`, default 10 / 15 min),
  applied in `lib/auth-actions.ts` before credential verification.
- **Auth e2e.** `apps/web/e2e/auth.spec.ts` runs against a **second** server on
  `:3001` started with auth env (`chromium-auth` project in `playwright.config.ts`);
  the default project ignores that spec. Covers redirect, bad credentials, and
  sign-in/sign-out. `CardTitle` is a `div`, not a heading — assert on labels, and
  scope `role="alert"` to `p[role='alert']` (Next's route announcer also has
  `role="alert"`).
- **Strict CSP (nonce).** `apps/web/proxy.ts` now generates a per-request nonce
  and sets `Content-Security-Policy` with
  `script-src 'self' 'nonce-…' 'strict-dynamic'` (no `'unsafe-inline'`); the
  static headers stay in `next.config.js`. The root layout reads `x-nonce` and
  passes it to `ThemeProvider` (`next-themes` supports a `nonce` prop). A nonce
  forces **dynamic rendering** — the build route table flips `/`, `/about`,
  `/components`, `/settings` from `○` to `ƒ`. That is the deliberate cost.
  `style-src` keeps `'unsafe-inline'` for inline style attributes. Dev keeps
  `'unsafe-eval'` (React needs it). e2e asserts the nonce is present, that
  `'unsafe-inline'` is gone from `script-src`, and that a browser run logs no CSP
  violations.
- **Gitignore.** Root `.gitignore` had duplicated `coverage`/Playwright blocks;
  deduped. `apps/web/.gitignore` already ignores `/playwright-report/`.
- Full suite after this pass: **79 unit tests + 28 e2e**, all green; `pnpm audit`
  clean.
- **Dev origins.** Next 16 blocks cross-origin dev assets; set
  `ALLOWED_DEV_ORIGINS` (comma-separated hostnames, declared in `turbo.json`
  `globalEnv`) when exposing `next dev` via a tunnel.

## Theme swap (OpenLynk)

- `packages/ui/src/styles/globals.css` now mirrors
  `openlynk-v2/src/app/globals.css`: neutral OKLCH palette (light) + a blue-tinted
  dark palette (`oklch(0.12 0.012 260)` etc.), `@theme inline` radius scale
  (`--radius-sm` = `radius * 0.6` … `--radius-4xl` = `radius * 2.6`), and the
  `obsidia-glass` / `obsidia-glass-hover` / `obsidia-pill` / `obsidia-glow-radial`
  utilities (renamed from the upstream `rune-*` prefix).
- **The `obsidia-*` utilities are theme-aware, not dark-only.** Upstream hardcodes
  `rgba(18, 18, 24, …)` glass + white text, which is unreadable on this app's
  light theme. They now read `--obsidia-*` tokens declared in `:root` (light) and
  `.dark`; the dark values are byte-identical to upstream, the light values invert
  to a white glass surface with slate borders/text. Keep new usages in mind when
  editing those tokens.
- Applied in the app: hero `obsidia-pill` + decorative `obsidia-glow-radial` and
  `obsidia-glass obsidia-glass-hover` feature cards
  (`apps/web/app/(marketing)/page.tsx`), `obsidia-glass` on the marketing header
  (`components/site-header.tsx`) and the app sidebar (`app/(app)/layout.tsx`), and
  a **Surfaces** section in `components/ui-showcase.tsx` that exercises all three
  (covered by the "renders the obsidia surface utilities" e2e test, which also
  asserts the light-theme glass is not the dark-only color).
- The new file imports `shadcn/tailwind.css`, so `shadcn` (catalog `^4.23.0`) is a
  `@repo/ui` dependency. That import supplies the shadcn custom variants
  (`data-open`, `data-closed`, `data-checked`, `data-unchecked`, `data-selected`,
  `data-disabled`, `data-active`, `data-horizontal`, `data-vertical`) plus the
  `no-scrollbar`, `scroll-fade*` and `shimmer*` utilities. Only the `scroll-fade`
  utilities ship into the app CSS today (Tailwind emits utilities on use).
- Kept the two `@source` lines (`apps/**` + `packages/**`) from the previous file —
  the CSS lives in `packages/ui` but must scan the whole monorepo. The only
  difference from the upstream file is those two directives.
- Fonts: the file keys `--font-sans` off a `--font-sans` var, but `apps/web`
  registers Geist as `--font-geist-sans` / `--font-geist-mono` (matching upstream's
  `--font-geist-mono`). So `--font-mono` picks up Geist Mono; the sans fallback
  stack is used. Point `Geist({ variable: "--font-sans" })` if the sans font
  should follow too.
- Verified: `pnpm build`, `check-types`, `lint`, `test` (45 unit), `test:e2e`
  (28) and `pnpm format:check` all green.
